# dbt_utils test models: Exasol copies

The test project runs the upstream dbt_utils test models and tests
(`dbt_packages/dbt_utils/integration_tests/models/{datetime,generic_tests,geo,sql}`
and `.../tests`). This folder holds Exasol copies of the few upstream models that
cannot run unchanged. The upstream original of each copy is disabled in
`integration_tests/dbt_project.yml`; the upstream `schema.yml` tests attach to the
copy by model name.

## Generated copies

Upstream models name CTEs `data` or `source`. Both are reserved words in Exasol:

```sql
-- Upstream (fails on Exasol): syntax error, unexpected DATA_
with data as (select 1) select * from data
-- Copy
with test_data as (select 1) select * from test_data
```

`create_overrides.sh` finds these models, copies them here and renames the CTE.
Generated files start with `-- Generated by create_overrides.sh`. Do not edit them.
Run the script after `dbt deps` whenever the dbt_utils version changes:

```bash
cd integration_tests
./create_overrides.sh
```

The script also rewrites the disable list between the `BEGIN/END create_overrides.sh`
markers in `dbt_project.yml`.

## Hand-written copies

Files without the generated header are written by hand. The script never
overwrites them. Each one says at the top why it exists:

- The seed has a reserved word as a column name (`OUTPUT`, `VALUE`, `CONDITION`,
  `MONTH`), so the seed is loaded with quoted lowercase columns and the model
  refers to them quoted.
- Exasol returns unquoted column names in uppercase. Upstream does not adjust
  for this on Exasol (`unpivot`, `pivot`, `star` with prefix/suffix).

`generic_tests/schema.yml` has Exasol copies of upstream tests on seeds with quoted
columns. The upstream versions of those tests are disabled under `data_tests:` in
`dbt_project.yml`.
